سرعان ما يصبح التواصل اليدوي عائقاً: تتراكم البيانات في جدول، وتُنسى المتابعات، ولا يعرف أحد بدقة أين وصل كل عميل. **n8n** يحل هذه المشكلة دون بناء تطبيق كامل.

## الحاجة الحقيقية

كنا نبحث عن نظام بسيط قادر على:

- جمع الطلبات الواردة في مكان واحد؛
- تأهيل كل عميل محتمل حسب ميزانيته وحاجته؛
- إشعار الفريق فقط بالعملاء المناسبين؛
- تفعيل متابعة بعد ثلاثة أيام دون رد.

وكان يجب أن يبقى كل ذلك مفهوماً لشخص غير مبرمج.

## سير العمل في أربع خطوات

1. **المُشغِّل**: يستقبل webhook بيانات نموذج الموقع.
2. **التوحيد**: تُنظَّف الحقول وتُحذف التكرارات.
3. **التأهيل**: يوجّه عقد شرطي العملاء الجادين إلى Slack.
4. **المتابعة**: انتظار ثلاثة أيام قبل إرسال بريد مخصص.

> [!TIP]
> ابدأ بسيناريو واحد وقناة واحدة. سير العمل الضخم يصعب تصحيحه.

## الجزء التقني

يعيد الـ webhook كائناً JSON موحّداً:

```json
{
  "name": "Amina",
  "email": "amina@example.com",
  "budget": 8000,
  "need": "إعادة تصميم الموقع"
}
```

داخل n8n، يمكن لعقدة **Code** حساب درجة بسيطة:

```js
const budget = Number($json.budget) || 0;
const need = String($json.need || "").toLowerCase();

const score = (budget >= 5000 ? 2 : 0) + (need.includes("موقع") ? 1 : 0);

return [{ json: { ...$json, score } }];
```

ثم ترسل عقدة **IF** النتائج من 2 فما فوق إلى Slack، والباقي إلى سلسلة رعاية تدريجية.

> [!WARNING]
> تحقق دائماً من التكرار قبل إرسال أي بريد. المتابعة المزدوجة أغلى من المتابعة المنسية.
